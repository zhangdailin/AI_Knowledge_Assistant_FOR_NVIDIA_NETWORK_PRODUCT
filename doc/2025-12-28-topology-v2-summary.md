# 混合模式拓扑还原系统 V2 (Hybrid Topology Restoration) 工作总结
**日期:** 2025-12-28
**版本:** v2.0
**状态:** 已上线

## 1. 项目背景与目标
原有的拓扑还原功能在处理大规模网络（>500 节点）时面临严重的性能瓶颈，主要表现为：
- **加载慢**：一次性传输大量 JSON 数据导致首屏等待时间长。
- **渲染卡顿**：ReactFlow (基于 DOM) 在几千个节点时 DOM 节点数量爆炸，导致浏览器卡顿。
- **内存占用高**：前端保存所有节点信息，容易崩溃。

**本次重构目标**：实现对 2000+ 设备（Core/Spine/Leaf 三层架构）的流畅渲染，提升用户体验。

## 2. 核心架构升级

### 2.1 混合渲染引擎 (Hybrid Rendering)
采用了根据节点数量自动切换渲染引擎的策略：
- **< 500 节点**: 继续使用 **ReactFlow** (DOM)，保留富交互特性（自定义 HTML 节点、Tooltip）。
- **> 2000 节点**: 自动切换至 **Cytoscape.js** (Canvas)，利用 Canvas 的高性能绘制能力，支持数万节点流畅交互。
- **中间态**: 使用 ReactFlow + 虚拟化技术（Virtual Viewport，仅渲染视口内元素）。

### 2.2 流式分层加载 (Streaming Layered Loading)
重构了后端 API (`/api/topology-restore-v2`)，采用 **NDJSON** 格式进行流式传输：
1. **Meta**: 先发送元数据（节点数/层级），前端立即初始化画布。
2. **Core/Spine**: 优先发送核心骨干网络，确保首屏秒开。
3. **Leaf**: 分块（Chunked）流式传输叶子节点，并在前端渐进式渲染。
4. **Edges**: 最后传输连接关系。

### 2.3 POD 级按需加载 (Lazy Loading)
针对超大规模拓扑（如万级），实现了 **Lazy Mode**：
- **初始加载**: 仅加载 Core 和 Spine 层设备，不加载 Leaf。
- **按需加载**: 用户点击 POD 或搜索时，才请求 `/api/topology-pod-details` 加载该 POD 的叶子节点。
- **收益**: 极大降低了初始带宽消耗和内存占用。

## 3. 关键功能特性

### 3.1 深度搜索 (Deep Search)
解决了 Lazy Loading 模式下本地无法搜索未加载节点的问题：
- 前端 `handleSearch` 优先搜索本地已加载节点。
- 若未找到，自动调用后端 `/api/topology-search` 接口。
- 后端在完整拓扑中检索，返回节点信息和所属 POD。
- 前端自动加载目标 POD 并高亮定位节点。

### 3.2 客户端高级布局
对于 Cytoscape 渲染模式，集成了 **CoSE-Bilkent** 布局算法：
- 支持 **"Smart Layout"**：一键整理混乱的拓扑，自动聚类 POD，减少由于初始坐标不准确导致的连线交叉。
- 支持 **"Preset Layout"**：复用后端计算的标准三层架构坐标。

### 3.3 边聚合 (Edge Bundling)
在 ReactFlow 模式下实现了边聚合算法：
- 将同一对源/目标设备间的多条物理链路合并为一条逻辑链路。
- 只有在选中或放大时才展开显示物理链路。
- 显著减少了 SVG 里的 Edge 数量（从几千减少到几百）。

## 4. 性能优化数据 (估算)

| 指标 | V1 (ReactFlow 全量) | V2 (Hybrid + Streaming) | 优化幅度 |
| :--- | :--- | :--- | :--- |
| **2500节点首屏时间** | > 10s (甚至卡死) | < 1s (Meta/Core) | **> 90%** |
| **FPS (交互帧率)** | < 10 FPS | > 50 FPS (Canvas) | **流畅** |
| **内存占用** | 高 (DOM泄漏风险) | 中 (按需加载) | **显著降低** |
